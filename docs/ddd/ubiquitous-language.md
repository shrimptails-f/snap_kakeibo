# ユビキタス言語

## 目的

本書は、snap_kakeibo の仕様、会話、設計、コードで同じ意味の言葉を使うための用語集である。

ここで定義した日本語を業務上の基準とする。API、DynamoDB、外部サービス固有の名前は境界で対応付け、技術上の都合を業務用語へ持ち込まない。

用語は実装に先立って完全に固定するものではない。仕様について会話する中で意味の違いが見つかった場合は、本書を更新してからモデルとコードへ反映する。

## 中心となる用語

| 用語 | 意味 | 対応する現在の名前・補足 |
| --- | --- | --- |
| 利用者 | この家計簿を使用し、自分の画像、支出、集計を所有する人 | `user` |
| レシート画像 | 利用者が家計簿への登録を目的として送信する画像 | S3 に保存される画像オブジェクト |
| アップロード | レシート画像の送信先を発行し、画像を受け付ける操作 | `POST /uploads` |
| 解析依頼 | 1枚のレシート画像について、受付から解析完了までを管理する対象 | 現在の `upload_history` に相当するが、「履歴」は保存形式を表す名前として扱う |
| 解析試行 | 解析依頼に対して実施される1回の解析処理 | `attempt` で識別する。最初の試行は1 |
| 再解析 | 完了できなかった解析依頼に対して、新しい解析試行を開始する操作 | `attempt` を1増やす。SQSによる同一試行の再配信とは区別する |
| 解析結果 | レシート画像から抽出された、確定前の店名、購入日、合計金額、明細 | OpenAIのレスポンスそのものではなく、外部レスポンスを変換した結果 |
| 支出 | 購入、取引、請求、返金などのうち、最終的に家計へ金額上の影響を与えるもの | 現在の `billing`。正式なコード名の変更は別途判断する |
| 支出明細 | 支出に含まれる商品またはサービスの1行 | 現在の `billing_detail` |
| 読取金額 | レシートに記載された、店舗側の値引きや税を反映済みの最終的な支払合計 | 現在の `original_amount` に対応する候補 |
| 調整額 | 読取金額に対して利用者が家計簿上で加減する符号付き金額 | 現在の `discount_amount` に代わる概念。減額は負数、増額は正数 |
| 計上額 | 月次集計へ反映する支出の金額 | 現在の `final_amount` に対応する候補。`読取金額 + 調整額` |
| 購入日 | 商品またはサービスを購入した暦日 | 時刻を含まない |
| 対象月 | 支出または集計が属する暦月 | `YYYY-MM` 形式。購入日から決まる |
| カテゴリ | 支出明細の用途分類 | 食費、日用品、医療などの定義済み分類 |
| カテゴリ決定元 | カテゴリをAIと利用者のどちらが最後に決めたか | 現在の `category_source` |
| 月次集計 | ある利用者の対象月に属する支出を集計した結果 | 計上額、支出数、明細数、カテゴリ別金額を含む。家計簿コンテキストの読み取りモデル |
| 月次再集計 | 保存済みの支出と支出明細から月次集計を作り直す操作 | 集計の復旧および支出編集の反映に使用する |

## 解析依頼の状態

| 用語 | 意味 | 保存値 |
| --- | --- | --- |
| アップロード待ち | 画像の送信先を発行済みで、画像がまだ受け付けられていない状態 | `UPLOADING` |
| 解析中 | 画像を受け付け、現在の解析試行が完了していない状態 | `ANALYZING` |
| 登録完了 | 解析に成功し、支出として登録された状態 | `SUCCEEDED` |
| 登録対象なし | 解析は完了したが、明細が1件もなく支出を登録しなかった状態 | `NO_DATA` |
| 解析失敗 | 解析は完了したが、検証違反などにより支出を登録できなかった状態 | `FAILED` |
| 期限切れ | アップロード待ちのまま送信先の有効期限を過ぎた表示上の状態 | 永続化する状態ではない |
| 停滞 | 解析中のまま所定時間を過ぎた表示上の状態 | 永続化する状態ではない |

## 失敗と再試行

| 用語 | 意味 |
| --- | --- |
| 業務上の失敗 | 日付や金額の不備など、現在の解析結果から支出を登録できないこと。解析依頼を解析失敗として終わらせる |
| 一時的な失敗 | 通信障害、レート制限、スロットリングなど、同じ解析試行の再実行で回復する可能性がある失敗 |
| 同一試行の再配信 | SQSが同じ `attempt` のメッセージを再度配信すること。再解析ではない |
| 古い試行 | 解析依頼が保持する現在の試行番号より小さい解析試行。結果は反映しない |
| 重複処理 | 同じ解析試行が並行して処理されること。最初に確定した終端結果のみを反映する |

解析中の依頼をいつ再解析可能とみなすか、および停滞を判定する時間は未決定とする。

## 金額の扱い

計上額は次の式で求める。

```text
計上額 = 読取金額 + 調整額
```

調整額は符号付きとする。

| 調整額 | 意味 |
| ---: | --- |
| `0` | 読取金額をそのまま計上する |
| 負数 | 割り勘、立替回収、返金などを反映して計上額を減らす |
| 正数 | 読み取り漏れ、追加費用などを反映して計上額を増やす |

計上額は返金を表現できるように負数を許容する。初期構成では、画像解析で得る読取金額は正数に限定し、返金は元の支出に負の調整額を設定して表現する。返金を独立した負数の支出として登録する機能は、必要になった時点で追加する。

### 店舗側の値引き

店舗側の値引きは読取金額へすでに反映されているものとして扱い、家計簿側で推測または再計算しない。

```text
商品小計       1,200円
店舗値引き      -200円
支払合計       1,000円

読取金額       1,000円
調整額             0円
計上額         1,000円
```

店舗値引きの行は支出明細へ含めず、計上額へ再適用しない。支出明細の合計と読取金額が一致しないことは許容する。

## カテゴリ

初期構成では、カテゴリを次の語彙に限定する。

| 保存値 | 表示上の意味 |
| --- | --- |
| `food` | 食費（日常の食事、食料品） |
| `daily_goods` | 日用品 |
| `medical` | 医療 |
| `transport` | 交通 |
| `utilities` | 水道・光熱・通信 |
| `entertainment` | 娯楽 |
| `social` | 交際・会食 |
| `clothing` | 衣類 |
| `education` | 教育 |
| `other` | その他 |
| `unknown` | 分類不能 |

`unknown` は分類できなかったことを表す。既知のカテゴリに当てはまらないことが分かっている `other` とは区別する。

`social` は、職場や友人との飲み会、会食、贈答など、人との関係を主な目的とする支出に使用する。日常の食事は `food`、個人的な趣味や余暇は `entertainment` とし、飲食を伴うかではなく支出の主な目的で分類する。

## 使用を避ける曖昧な言葉

| 言葉 | 問題 | 代わりに使う言葉 |
| --- | --- | --- |
| データ | 何を指すか分からない | レシート画像、解析結果、支出、支出明細など |
| 処理 | 操作や状態遷移が分からない | 解析を開始する、支出を登録する、月次集計を再構築するなど |
| リトライ | 同一試行の再配信と新しい試行が混同される | 同一試行の再配信、再解析 |
| 金額 | 読取金額、調整額、計上額、明細金額が混同される | 対象となる具体的な金額名 |
| 履歴 | 解析対象と監査ログが混同される | 解析依頼、解析試行 |
| 請求 | 請求書や債務を扱うように読める | 業務会話では支出を使う。コード名の移行は別途判断する |

## 技術用語との境界

次の用語は実装上必要だが、ドメインモデルの名前としては使用しない。

- DynamoDBのテーブル名、PK、SK、GSI、Condition Expression
- S3のバケット名やオブジェクトキー
- SQSメッセージや再配信回数
- Lambda、API Gateway、HTTPステータス
- OpenAI Responses APIのレスポンス形式、`refusal`、トークン数

これらは application、infrastructure、HTTPハンドラなどの境界で、上記の業務用語へ変換する。
