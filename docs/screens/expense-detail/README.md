# 支出詳細・編集画面

## 目的

レシート画像1枚から作成された支出と支出明細を確認し、必要に応じて修正する。

割り勘や立替回収で、最終的に自分が負担する金額(計上額)が変わるケースを扱う。

---

## 画面設計

実装対象: [Issue #79](https://github.com/shrimptails-f/snap_kakeibo/issues/79)(親: [#77](https://github.com/shrimptails-f/snap_kakeibo/issues/77)) の支出詳細・編集画面。
画面は `/expenses/:expenseId` に実装する。以下のワイヤーフレームと操作モックは、実装が満たす画面構成と状態の正本とする。

### 操作できるモック

[mock.html](./mock.html) をブラウザーで開くと、サンプルの支出を使って閲覧・編集・保存を試せる。APIには接続せず、保存内容はページを再読み込みすると初期値に戻る。レシートも表示確認用の見本とする。

`編集する` → 調整額や明細を変更 → `変更を保存` の順に操作する。`次の保存を失敗させる` はモック専用の確認操作で、入力を残したまま保存に失敗する状態を試せる。画像の拡大と未保存変更の破棄確認も操作可能。戻り先の一覧画面はこのモックの対象外。

ローカルサーバーで確認する場合は、リポジトリルートで次を実行し、`http://localhost:4173/mock.html` を開く。

```sh
python3 -m http.server 4173 --directory docs/screens/expense-detail
```

### 設計方針

スマートフォンでレシートを取り込んだ利用者が、画像とAI読み取り結果を見比べ、必要な箇所だけ修正して保存するための画面とする。

[デザインガイドライン](../../../front/docs/design_guidelines.md) に合わせ、白背景と落ち着いた緑を使う、読みやすい家計簿の作業画面にする。計上額を最も強く示し、その根拠となる読取金額と調整額を近くに置く。画像と入力欄の位置関係を保ち、修正中に比較対象を見失わないことを重視する。

- 詳細と編集は同じページ `/expenses/:expenseId` に置く。初期表示は閲覧状態で、`編集する` からフォームに切り替える。
- 保存対象は支出と既存の全明細。明細の追加・削除、支出の削除、再解析は今回の対象外。
- 自動保存は行わない。`変更を保存` で一括保存し、同じ画面の閲覧状態へ戻る。
- 金額、店舗・日付、明細の順に確認する。画像はその確認を補助する。

### 記号の凡例

`[ 操作 ]` はボタン、`< 戻る` はリンク、`[ 値 ____ ]` は入力欄、`[ 値 v ]` は選択欄。`AI解析`、`編集済み`、`未保存` は文字による状態表示。図中の店舗・商品・金額は説明用の例。

右側の支出情報・編集領域はページと一緒に利用者がスクロールする。編集への切り替え、保存通知、キャンセル、画像からの復帰ではフォーカス移動に伴う自動スクロールを行わない。スムーズスクロールも適用しない。閲覧への切り替えでページが短くなる場合は、ブラウザーが表示可能な範囲に位置を収める。

- モバイルの画像領域は最大30vhの設計目安とし、画像を開いたままフォームを操作できる。画像を固定し続けず、ページと一緒にスクロールさせる。
- 拡大表示は全画面ダイアログ。`拡大`、`縮小`、`全体を表示`、`閉じる` を文字付きで用意し、ピンチ操作だけに依存しない。拡大時の画像内スクロールは許容し、ページ全体の横スクロールは発生させない。

### 金額と入力ルール

| 項目 | 表示・編集ルール |
| --- | --- |
| 店舗名・商品名 | 必須。空白のみを許容しない。長い名称は閲覧時に折り返す |
| 購入日 | 必須。実在する暦日。変更で月が変わる場合は「保存すると2026年10月の支出になります」と表示する |
| 読取金額 | 参照専用。店舗の値引き・税が反映された支払合計 |
| 調整額 | 必須。初期値は保存済みの値。円単位の符号付き整数。負号を入力できる操作を用意する |
| 計上額 | 直接編集しない。調整額の入力に合わせ即時再計算する。0円・負数も許容する |
| 明細金額 | 必須。0〜10,000,000円の整数。数量を掛けて自動更新しない |
| 数量 | 必須。1〜999の整数。数量の変更で明細金額・計上額を自動更新しない |
| カテゴリ | 必須。[用語集](../../ddd/ubiquitous-language.md#カテゴリ)の全11分類を日本語表示する。分類不能も有効な選択肢 |

明細合計は `details[].amount` の合計。読取金額との差だけではエラーにせず、保存を妨げない。カテゴリ別内訳は明細金額に基づく補助情報であり、調整額を各明細に自動配分しない。

調整額が空欄や `-` だけなど入力途中の場合、保存後の計上額は「入力中」とし、誤った数値を表示しない。保存は無効にして理由を近くに示す。桁区切りと円表記は閲覧時に付け、入力欄では数値と単位を分離する。負の計上額には「返金などにより、今月の支出を減らす金額です」と補足する。

### AI解析・編集済み・未保存

表示は短く「AI解析」「編集済み」とする。「明細:」の接頭辞は付けない。「AI解析」の横に小さな丸囲みの `i` ボタンを置き、説明は常時表示しない。内部の `source` / `is_edited` / `category_source` の意味や判定は変更しない。

説明は「※『AI解析』は、AIがレシートを解析した結果です。」。マウスでは短い待ち時間を設けたホバー、スマートフォンではタップ、キーボードではフォーカスで表示する。クリック・タップで開いた説明は、領域外のクリック・タップ、同じボタンの再操作、Escで閉じる。ホバー中は説明の上へポインターを移しても閉じない。画面内に一つだけ表示し、スクロールやフォーカス移動で閉じる。説明は本文に重ね、レイアウトやスクロール位置を動かさず、画面端からはみ出さない。アイコンは小さくても操作領域は44pxを確保する。

| 対象 | 判定と表示 |
| --- | --- |
| 支出全体 | `expense.is_edited` がtrueなら「編集済み」、falseかつ `source = AI` なら「AI解析」 |
| 各明細 | 明細の `is_edited` と `source` で同様に表示する |
| カテゴリ | `category_source = AI` は「AI解析」、`USER` は「編集済み」。編集フォームで選択欄に添える |
| 今回の変更 | 保存済みの値と異なる入力欄に「未保存」。元の値へ戻したら消す |

`source = USER` も「編集済み」とする。由来が不明な値はAIと推測せず「由来不明」とする。支出や明細単位の編集済み情報から、店舗名や商品名など個別項目の編集履歴を推測しない。保存成功までは保存済みの由来表示を維持し、今回の変更と区別する。AIの信頼度や過去の原文はAPIにないため表示しない。

### 画面状態と操作

| 状態 | 表示 | 操作・遷移 |
| --- | --- | --- |
| 初回取得中 | 共通の読み込み表示「支出を読み込み中」 | 戻るリンクを残す。編集はまだ表示しない |
| 取得失敗 | 「支出を読み込めませんでした」 | `再読み込み` と戻るリンク。再取得中は連打を防ぐ |
| 支出なし | 「支出が見つかりません」 | 一覧へ戻る。他人の支出との違いを示さない |
| 閲覧 | 保存済み情報 | `編集する` でフォームへ |
| 編集開始・変更なし | 入力可能なフォーム。「変更はありません」 | 保存は無効。キャンセルで閲覧へ |
| 編集中・変更あり | 「変更あり・未保存」、保存後の計上額 | 入力が有効なら保存可能 |
| 入力エラー | 入力直下に具体的なエラー、フォーム上部にエラー一覧 | 一覧から該当入力へ移動。入力値を維持する |
| 保存中 | 操作バーに「保存中…」 | 二重送信を防ぎ、フォームとキャンセルを無効化。アプリ内遷移を抑止する |
| 保存成功 | 閲覧に戻り「変更を保存しました」。計上額と保存済み内容を更新 | 同じページに留まり、戻るか再編集できる |
| 保存失敗 | 「変更を保存できませんでした。入力内容は残っています」 | 入力値を維持し、修正または `変更を保存` で手動再試行。自動再送しない |
| 保存後の再取得失敗 | 「保存は完了しましたが、最新の表示を取得できませんでした」 | 保存を再送せず `最新の内容を読み込む` を表示する |
| 明細なし | 「支出明細がありません」 | 想定外の状態として再読み込みと戻るを提供。正常な支出では明細は1件以上 |
| 画像読み込み中・失敗 | 画像領域だけに進行表示、または「画像を表示できません」 | 画像の再試行を提供。支出の確認・編集・保存は続けられる |

初回取得には共通の `Suspense` / `ErrorBoundary` を利用する。再取得中は既存内容を維持し、定期取得はしない。入力エラーはblurまたは保存操作時に表示し、修正で解消する。HTTPステータスや内部エラーを利用者にそのまま見せない。

```text
閲覧 --[編集する]--> 編集 --[変更を保存]--> 保存中
 ^                    |                       |
 |                    |                       +-- 成功 --> 閲覧＋保存通知
 +--[キャンセル]------+                       |
                      ^                       +-- 失敗 --+
                      +--------- 入力内容を保持 ---------+
```

未保存の変更がある状態でキャンセル・戻る・アプリ内の別画面への移動を選んだら、次の確認を出す。変更がなければ確認せず移動する。タブを閉じる・再読み込みにはブラウザー標準の離脱確認を使用し、閉じた後の入力復元は保証しない。

```text
┌────────────────────────────────────┐
│ 変更を破棄しますか？               │
│ 保存していない変更は失われます。   │
│ [ 編集を続ける ] [ 変更を破棄する ] │
└────────────────────────────────────┘
```

### 戻り先

- 月別支出から来た場合は、元の月と一覧位置へ戻る。購入月を変更して保存した場合も戻り先は元の一覧とし、保存通知に変更後の月別支出へのリンクを添える。
- アップロード完了・解析依頼一覧から来た場合は、その遷移元へ戻る。リンクの文言も「アップロードへ」「解析依頼一覧へ」に合わせる。
- URLから直接開いた場合は、取得した購入日の月別支出 `/months/:yearMonth` へ戻る。取得前・取得失敗・支出なしの場合は `/analysis-requests` へのリンクを表示する。
- 保存後は、変更前後の対象月の一覧・集計を次回表示時に再取得する。集計への反映が未確認の段階で「月次集計も更新済み」とは表示しない。

### 見た目とアクセシビリティ

- 色は既存トークンを使用。白背景、本文 `--color-text`、主要操作 `--color-primary`、未保存はwarning、エラーはdangerとし、必ず文字も添える。
- 既存の日本語system font stackを継承。本文・入力16px、補足14px以上、計上額28〜32pxを目安とする。金額は桁幅を揃え、閲覧時は右寄せ。
- 余白は既存の8 / 16 / 24 / 32px。明細は区切り線で分け、商品ごとに影付きカードを重ねない。入力は既存の小さい角丸に揃える。
- 入力には常時ラベルを表示し、明細番号を含めた名前と、補足・エラーの関連付けを持たせる。すべての操作領域は44px以上。
- DOM順は見た目の順と合わせる。編集開始時はフォーム見出し、保存成功時は完了通知へフォーカスを移す。保存状態はライブ領域で通知し、計上額の更新を打鍵ごとに過剰に読み上げない。
- 画像ダイアログ・破棄確認ではフォーカスを閉じ込め、Escで閉じて操作元へ戻す。画像には「この支出のレシート画像」と代替テキストを付ける。
- hoverだけに依存せず、キーボードのfocusを明示する。開閉や状態変化は短くし、`prefers-reduced-motion` で動きを抑える。

### 実装時の確認項目

画面実装では次の条件でブラウザー検証する。

- 360 / 390 / 768 / 1280pxで、横スクロール・文字切れ・操作の重なりがない。
- 画像の比較、拡大、閉じる操作の前後で、入力値・フォーカス・スクロール位置を保持する。
- 計上額の強調、金額の桁揃え、常時ラベル、状態の文字表示、明細の区切り、focus表示を確認する。
- 調整額0・正数・負数・入力途中・計上額が負数になる場合、明細金額0円・数量999・長い商品名・50件の明細を確認する。
- 取得失敗、画像失敗、保存失敗、保存成功、未保存での離脱、購入月変更を操作して確認する。
- ソフトウェアキーボード、safe area、キーボードのみの操作、動きを減らす設定を確認する。

## 編集対象

```text
店舗名

購入日

調整額

商品名

商品金額

数量

カテゴリ
```

調整額を変更した場合は、支出単位の計上額を再計算する。調整額は符号付きで、減額は負数、増額は正数。

```text
read_amount + adjustment_amount = recorded_amount
```

計上額は返金を表現できるように負数を許容する。

## API設計

### GET /expenses/{expense_id}

支出単位の詳細と支出明細を取得する。利用者の支出に `expense_id` が無ければ `404`(他人の支出も同じ)。

Response:

```json
{
  "expense": {
    "expense_id": "01JEXPENSEXXX",
    "analysis_request_id": "01JREQUESTXXX",
    "store_name": "スーパー",
    "purchase_date": "2026-09-15",
    "year_month": "2026-09",
    "read_amount": 3280,
    "adjustment_amount": -500,
    "recorded_amount": 2780,
    "source": "AI",
    "is_edited": false,
    "updated_at": "2026-09-15T12:10:00Z",
    "image_url": "https://example.com/presigned-receipt-url"
  },
  "details": [
    {
      "detail_id": "01JITEMXXX",
      "name": "牛乳",
      "category": "food",
      "category_source": "AI",
      "amount": 281,
      "quantity": 1,
      "source": "AI",
      "is_edited": false
    }
  ]
}
```

`details` は `detail_id`(ULID)の昇順 = 採番順。

`expense.image_url` は元画像を取得する15分有効の署名付きGET URL。画像の読込に失敗した場合、画面は同じGETを再実行してURLだけを更新し、編集中のフォーム値は上書きしない。backend / frontend の独立デプロイ中に旧backendがこのフィールドを返さない場合は、画像未取得の案内を表示して支出の確認・編集を継続できる。

### PATCH /expenses/{expense_id}

支出単位の情報と既存の全支出明細を更新する。支出と明細は1回のDynamoDB transactionで保存し、保存後に対象月の月次集計を正本から再構築する。購入月が変わる場合は旧月と新月の両方を再構築する。

保存成功後はGETで全項目と由来情報を再取得する。以下のPATCHレスポンスだけでは店舗名・購入日・明細・編集済み情報が揃わないため、再取得を含めて表示を確定する。PATCH成功後にGETだけが失敗した場合は、保存失敗と区別して扱う。

調整額は JSON / Go の符号付き整数として受け付け、フロントエンドでは JavaScript の安全な整数に限定する。店舗名・商品名は空白だけを許容しない。明細IDは保存済みの全件を重複なく指定し、追加・削除は受け付けない。支出自体の楽観ロックは持たず後勝ちとし、月次集計の再構築だけ `version` の条件更新を最大3回やり直す。明細金額は数量込みの `amount` をそのまま保存・集計し、数量を掛け直さない。

Request:

```json
{
  "store_name": "スーパー",
  "purchase_date": "2026-09-15",
  "adjustment_amount": -500,
  "details": [
    {
      "detail_id": "01JITEMXXX",
      "name": "牛乳",
      "amount": 281,
      "quantity": 1,
      "category": "food"
    }
  ]
}
```

Response:

```json
{
  "expense": {
    "expense_id": "01JEXPENSEXXX",
    "read_amount": 3280,
    "adjustment_amount": -500,
    "recorded_amount": 2780,
    "updated_at": "2026-09-15T12:10:00Z"
  }
}
```
