# 月別支出画面

## インタラクティブモック

[mock.html](./mock.html) をブラウザで直接開くと、画面幅に応じたレイアウトと主要操作を確認できる。前月・翌月、年月選択、再読み込み、明細から支出詳細を開く操作に対応している。ページ末尾の「モックの状態を変更」から、通常・初回取得中・空・再取得失敗・部分取得失敗・全体失敗・集計不整合・0円・負数の表示を切り替えられる。

このモックは画面設計の確認用であり、API通信、URL遷移、認証、アップロード、支出の編集・保存は行わない。月ごとの値は一部のサンプルだけを内蔵し、未実装画面へのリンクは通知またはダイアログで代替している。

ローカルサーバーで開く場合は、リポジトリルートで次を実行し、`http://localhost:4175/mock.html` を開く。

```sh
python3 -m http.server 4175 --directory docs/screens/monthly-expenses
```

モックはPlaywright / Chromiumで360px・390px・768px・1280pxの表示と横はみ出しがないことを確認。月切り替え、金額の整合、詳細の開閉、空・部分失敗・全体失敗・0円・負数の状態、再試行と連打防止も確認した。スクリーンショットで文字階層・金額位置・余白・区切り線・グラフと表の対応ラベルを確認した。

## 目的

指定月の計上額とカテゴリ別内訳を確認し、気になる明細から支出詳細へ進む。

実装対象: [Issue #83](https://github.com/shrimptails-f/snap_kakeibo/issues/83)（親: [Issue #77](https://github.com/shrimptails-f/snap_kakeibo/issues/77)）。React 画面は `/months/:yearMonth`、月別明細 API は `GET /api/months/{yyyy-MM}/expenses` で提供する。

## 設計方針

- 対象は、取り込んだレシートを月単位で振り返りたい利用者。月合計 → カテゴリ内訳 → 明細 → 支出詳細の順に確認する。
- [デザインガイドライン](../../../front/docs/design_guidelines.md) §1〜8 に合わせ、白背景と落ち着いた緑、区切り線主体の読みやすい家計簿とする。
- 特徴は「大きい支出を見つけ、その場で根拠の明細へたどれる」こと。情報をカードに分散させず、金額の右端を揃える。
- 月合計は計上額、カテゴリ内訳と明細は明細金額。意味が異なるため、円グラフの中央に月合計を入れない。
- 上部にカテゴリ内訳の円グラフと同じ数値の表、下部に金額降順の明細付き横棒グラフを置く。表と棒のラベルだけでも全内容を確認できる。
- 表示上限・ページネーションは設けない。長い一覧はページ全体で縦スクロールする。

## 記号の凡例

`[ 操作 ]` はボタン、`リンク >` は遷移、`[ 値 v ]` は選択欄、`■` は金額に比例する棒。円グラフの `A / B / C` はカテゴリを対応付けるラベル例。日時・金額・件数はすべてサンプルで、図中の省略は表示上限を意味しない。

## 表示と操作

### 月の切り替え

- URLは `/months/:yearMonth`（例: `/months/2026-09`）。購入日が属する月を表示し、画像の受付月とは区別する。
- 前月・翌月は対象月へ移動するボタン。年をまたいで移動できる。年月選択は月入力欄で任意の年月を選び、確定時に移動する。入力中の不完全な値では取得しない。
- 月変更時は本文先頭へ戻す。取得中に前の月の数値を新しい月の値として表示しない。素早く切り替えても、遅れて返った別月の結果で上書きしない。
- 不正な年月のURLには「指定された月を表示できません」と `今月を開く` を示す。
- `再読み込み` は月次集計と明細を取得し直す。自動pollingは行わず、再取得中と押下後3秒間は連打を防ぐ。クールタイム中は他画面と共通のボタンで残り秒数を示す。

### 月合計と内訳

| 表示 | 値・ルール |
| --- | --- |
| 月合計（計上額） | `GET /monthly-summaries` の対象月の `total_recorded_amount`。明細合計で代用しない |
| 支出件数 | 対象月の `expense_count`。明細件数とは別に表示 |
| 明細件数 | 取得した `items.length`。数量の合計ではない |
| 明細合計 | 対象月の確定した `items[].tax_included_amount`、未確定行の `items[].amount` の合計。数量を掛けない |
| 集計更新 | 対象月の `updated_at` を日本時間に変換して表示する。集計の再構築日時であり、購入月の登録完了を意味しない |
| カテゴリ金額 | 取得した明細を `category` ごとに合計。現在の保存値を使用し、利用者が修正した値を優先 |
| 割合 | カテゴリ金額 ÷ 明細合計。小数1桁に丸め、丸めにより合計が100%にならない場合があると補足 |

- 円グラフと表は同じ集計を使う。カテゴリの凡例と円グラフは[デザインガイドラインの共通色](../../../front/docs/design_guidelines.md#カテゴリの共通色)の定義順に並べる。登場しないカテゴリは省き、明細がある0円のカテゴリは表に残す。
- カテゴリ名は上記定義に合わせる。`unknown` は「分類不能」、`other` は「その他」として区別し、少額カテゴリも「その他」にまとめ直さない。
- 支出明細の横棒も円グラフ・表と同じカテゴリ色を使う。色だけに頼らずカテゴリ名を併記する。
- 円グラフはカテゴリ名・金額・割合を表で常時確認できる。色だけに依存せず、対応ラベルを付ける。hover、タップ、ツールチップを情報取得の前提にしない。
- 月合計が0円・負数でも正常な値として表示する。負数の場合は「返金などの調整により、今月の計上額はマイナスです」と補足する。
- 内訳がすべて0円なら円グラフを描かず「明細金額の合計は0円です」と表示し、表の割合は「—」にする。負の明細金額を受け取った場合も円グラフ・割合を省き、符号付きの金額表を残す。
- 税込み額が未確定の行を含む場合、その件数と印字額を含めたことを示し、円グラフと割合を表示しない。明細行では確定した税込み額または「印字額・税込み未確定」を明示し、確定行にも元の印字額を併記する。
- 全明細の税込み額が確定し、明細合計が正で負数行がない場合だけ、各カテゴリの税込み額を税込み明細合計で割って割合を表示する。割合の分母に月の計上額を使わない。
- 月合計と明細合計の差を「調整額」と断定しない。読取金額と明細合計も一致するとは限らないため。差をエラー色にせず、説明を常時併記する。

### 明細一覧

- 金額降順を初期かつ固定の並び順とする。同額はAPIの順序を維持する。日付・店舗・カテゴリは各行に常時表示し、隠れた情報にしない。
- 横棒は月内の最大明細金額を基準に長さを揃える。棒の横または同じ行に金額を必ず表示する。0円は棒なしで「0円」、全件0円でも一覧を表示する。負数が含まれる場合は棒を省いて金額を表示する。
- スマートフォンは商品名と金額、その下に棒、購入日・店舗、カテゴリ・数量・由来を並べる。独立したカードにはせず区切り線で連続させる。
- 商品名・店舗名は折り返して全文を読めるようにする。狭い画面で金額と競合したら金額を次行の右端へ送り、文字を縮小しない。
- 明細全体を支出詳細への1つのリンクとし、右端の `>` で遷移を示す。リンク内に別のボタンを置かない。
- 表示上の由来は支出詳細に合わせ「AI解析」「編集済み」とする。`is_edited = true` を優先して「編集済み」、それ以外で `source = AI` なら「AI解析」、`source = USER` なら「手動登録」。これは明細全体の由来で、カテゴリ単独の由来とは断定しない。
- `expense_id` と `detail_id` は遷移・位置復元に使い、長い内部IDを通常表示しない。

## 画面遷移

```text
ダッシュボードで月を選ぶ
          |
/months/2026-09
          |
     明細を選ぶ
          |
/expenses/:expenseId  （支出詳細・編集）
          |
  < 2026年9月の支出へ
          |
元の月・明細の位置へ戻る
```

- 支出詳細は別ページとする。遷移元の月、明細ID、スクロール位置を履歴状態に保持する。直接アクセスした詳細の戻り先は購入日の月とする。
- 同じレシートに属する複数明細は同じ支出詳細へ進む。実装時に対象明細へフォーカスを移せるよう明細IDも渡す。
- 保存後は影響した月の集計と明細を再取得する。購入日を別月へ変更した場合は変更前後の月を更新する。戻った月から明細が消えた場合は「変更した支出は別の月に移動しました」と知らせ、一覧見出しへフォーカスを戻す。
- 空状態の `レシートを取り込む` は [アップロード画面](../upload/README.md) の `/upload` へ遷移する。

## 画面状態

| 状態 | 表示と回復操作 |
| --- | --- |
| 初回取得中 | 共通レイアウトの `Suspense` / `Spinner` で「月別支出を読み込み中」。未取得の値を0円にしない |
| 通常 | 月合計・内訳・全明細を表示。手動で再読み込み可能 |
| 再取得中 | 同じ月の表示を保ち、ボタンを「再読み込み中…」にする |
| 再取得失敗 | 同じ月の既存表示を保ち「更新できませんでした。前回取得した内容です」と再試行を表示 |
| 月次集計だけ失敗 | 月合計を「取得できませんでした」とし `月合計を再読み込み`。取得済みの内訳・明細・詳細リンクは利用可能 |
| 明細だけ失敗 | 月合計は表示し、内訳と一覧に「明細を読み込めませんでした」と `明細を再読み込み` |
| 両方失敗 | 「月別支出を読み込めませんでした」と `再読み込み`。月選択と戻る導線を残す |
| 空 | 明細0件かつ集計なし、または集計の支出件数・明細件数・計上額がすべて0なら、月合計0円と下記の空状態。取得成功後にのみ判定 |
| 集計と明細の不整合 | 明細があるのに対象月の集計がない、または件数が一致しない場合は「月合計と明細の情報が揃っていません」と再読み込み。推測した0円や明細合計で補わず、取得できた情報を表示 |
| 認証切れ | 共通の認証処理に従ってログインへ。空状態とは区別する |

```text
空状態                              明細の取得失敗
┌────────────────────────────┐      ┌────────────────────────────┐
│ 2026年9月                  │      │ 月合計（計上額）           │
│ 月合計（計上額） 0円       │      │ 12,000円                   │
│                            │      │ ────────────────────────── │
│ この月の支出はまだありません│      │ ! 明細を読み込めませんでした│
│ レシートを取り込む >       │      │ [ 明細を再読み込み ]       │
│ < 前月        翌月 >       │      │                            │
└────────────────────────────┘      └────────────────────────────┘
```

空状態では空の円グラフや棒のダミーを描かない。明細が存在する0円の月は通常状態であり、取り込みを促す空状態にしない。部分取得の失敗は領域単位の `ErrorBoundary` で受け、表示可能な領域を隠さない。

## 見た目とアクセシビリティ

- 色は既存の背景・本文・補助文字・境界線・主要色トークンを使う。緑は操作・選択状態を中心に使い、カテゴリの色に成功・失敗の意味を持たせない。
- 円グラフ・凡例・明細の棒とカテゴリ色見本は、デザインガイドライン §2「カテゴリの共通色」のトークンをカテゴリIDで参照する。月や金額順によらず同じ色に固定し、対応ラベルと境界線を併用する。画像・イラスト・装飾グラデーションは不要。
- 既存の日本語system font stack、本文16px、補助14px以上、月合計32pxを目安にする。金額は桁区切り・円単位・等幅数字で右揃え。
- 左右余白はモバイル16px、デスクトップ24px。領域間24〜32px、行内8〜12px。影のあるカードを繰り返さず、境界線でまとまりを示す。
- タップ領域は44px以上。月入力には「表示する月」、前月・翌月リンクには遷移先の年月を含む名前を付ける。キーボードでも月変更と明細選択が可能で、フォーカスを可視化する。
- カテゴリ表には見出しセルを使う。グラフが表・明細と完全に重複する場合は装飾扱いにして読み上げを重複させない。金額・由来・エラーは色だけで伝えない。
- グラフの登場アニメーションは付けず、再取得で棒を伸縮させない。動きは操作時の短い状態変化にとどめ、`prefers-reduced-motion` を尊重する。

## 実装時の確認項目

以下は本番画面と API を継続して確認するための検証項目。モックはサンプルデータを使う独立した設計資料である。

- 360px / 390px / 768px / 1280pxで月選択、円グラフと表、明細を確認し、横スクロール・金額の欠け・操作の重なりがない。
- 長い商品名・店舗名、全カテゴリ、明細多数、全件0円、負の計上額でも情報を読める。
- サンプルの13,500円の内訳が12,000円の月合計として誤表示されず、牛乳800円に数量2が再乗算されない。
- 月の年跨ぎ・直接URL・月の連続切り替え・再取得失敗・部分取得失敗・空状態を確認する。
- 明細 → 詳細 → 編集保存 → 元の月へ戻る操作で、合計・カテゴリ・並び順を更新できる。購入月の変更も確認する。
- 白背景、文字階層、金額の右揃え、余白、区切り線、長文の折り返し、フォーカス、色に依存しないラベルを確認する。

## 今回の対象外

- 並べ替え切り替え、検索、カテゴリ絞り込み、予算、前月比。まず全明細の金額比較と詳細への導線を成立させる。
- 月別画面での編集・削除・再解析・集計再構築。編集は支出詳細で行い、再読み込みは取得のみとする。

## API設計

### GET /months/{yyyy-MM}/expenses

`items[].amount` は印字額を維持する。`tax_included_amount` と `tax_rate` は確認できた行だけ返し、未確定の行では省略する。`tax_mode` は旧データで空の場合がある。並び順は確定した税込み明細額、未確定なら印字額の降順とする。

指定月の支出明細を取得する。
