# ダッシュボード画面

## 1. 目的

月ごとの計上額と前月からの変化を俯瞰し、気になった月の支出へ進む。

実装対象: [Issue #85](https://github.com/shrimptails-f/snap_kakeibo/issues/85)（親: [Issue #77](https://github.com/shrimptails-f/snap_kakeibo/issues/77)）。React 画面は `front/src/features/dashboard`、参照 API `GET /api/monthly-summaries` は [Issue #83](https://github.com/shrimptails-f/snap_kakeibo/issues/83) の実装を使用する。

表示と操作を単独で確認するための [HTMLモック](./mock.html) も残す。サンプルデータを使った設計資料であり、実際の画面は API に接続する React 実装を正とする。

- 主な利用者: レシートを取り込み、月ごとの支出を振り返りたい人。
- 主な操作: 月合計を比較する → 対象月の明細を見る → 必要なら支出詳細で修正する。
- 情報の優先順: 月合計と推移 → 月別支出への導線 → カテゴリ別の参考内訳。
- 設計の特徴: 「計上額の推移」と「明細ベースの内訳」を混ぜず、金額の意味を見出しから判断できる。

## 2. 設計方針

「帳簿のような一覧中心」「グラフ中心の分析画面」「落ち着いた家計の確認画面」を比較し、3つ目を採用する。月ごとの支出は棒グラフで比較し、正確な金額も各棒に添える。同じ月を繰り返し並べる月別一覧は設けない。

[デザインガイドライン](../../../front/docs/design_guidelines.md) §2〜8 に合わせ、白背景・落ち着いた緑・区切り線を使う。数字のカードを大量に並べず、1本の縦の流れで確認できる構成にする。

グラフは「カテゴリ別（明細）」の色付き積み上げと「計上額」の単独棒を切り替える。初期表示はカテゴリ別とし、積み上げの高さが明細合計であることを常時説明する。各棒に、選択中のモードの正確な金額（明細合計または計上額）を表示する。色は [デザインガイドライン §2](../../../front/docs/design_guidelines.md#カテゴリの共通色) の共通トークンを使う。

カテゴリ別の積み上げ棒を押すと、その月の内訳を下部に表示する。内訳の見出しに選択月を示し、月別支出へのリンクを隣に置く。グラフの月名から月別支出へ進む。「計上額」表示でも棒を押すと下部のカテゴリ別内訳だけを切り替える。

以下の記号図は「計上額」選択時の配置。カテゴリ別では同じ場所の棒を固定色で積み上げ、上に表示切替・説明・凡例を置く。PCは縦積み、モバイルは横積みにする。カテゴリ内訳の正確な値は下部の一覧で確認できる。

## 3. 画面構成と導線

```text
ダッシュボード /（本案の配置先）
  |
  +-- 表示期間を選ぶ（6か月単位）
  |     +-- 月ごとの計上額グラフ
  |
  +-- カテゴリ別の積み上げ棒を選ぶ → その月の明細金額を確認
  |
  +-- 月名・「明細を見る」 → /months/:yearMonth
  |                             → /expenses/:expenseId
  +-- レシートを取り込む → /upload
  +-- 解析履歴 → /analysis-requests
```

`/` はダッシュボード、`/upload` は取り込み、`/analysis-requests` は解析履歴とする。共通ヘッダーにはこれらと月別支出への導線を置く。

凡例: `[ 操作 ]` はボタン、`[ 値 v ]` は選択欄、`リンク >` は遷移、`■` は計上額の棒。図中の金額・件数・日時は設計用のサンプル。棒の長さは概形で、正確な値は各棒のラベルに示す。

## 6. 表示期間・操作

| 操作 | 振る舞い |
| --- | --- |
| 初回表示 | 現在月を終了月とした6か月を表示。参考内訳は期間内の集計がある最新月を選ぶ |
| 表示開始月を選ぶ | 選んだ月を先頭にし、表示終了月を5か月後へ更新する。取得済み一覧を使い、再取得しない |
| 表示終了月を選ぶ | 選んだ月を末尾にし、表示開始月を5か月前へ更新する。取得済み一覧を使い、再取得しない |
| グラフの月名を押す | `/months/{year_month}` へ遷移 |
| 明細を見る | 同じ月別支出画面へ遷移。0円の棒が見えない月でも利用できる |
| カテゴリ別または計上額の棒を押す | その月のカテゴリ別内訳に切り替える。選択中の棒は不透明、未選択は半透明、未選択のホバー中はその中間の不透明度にし、URLの `reference` に月を保存する |
| 再読み込み | `GET /monthly-summaries` を再取得。現在の表示期間と参考月を維持する |
| 月別支出から戻る | 表示期間、参考月、スクロール位置を復元する |

- 表示終了月の選択肢は最古の集計月から現在月まで。表示開始月の選択肢はそれぞれ5か月前とする。未来月の集計が返る場合はその最新月まで選択可能にし、終了月には「未来月」と明記する。
- 期間変更時、参考月が新しい期間内なら維持する。範囲外なら期間内の集計がある最新月へ、なければ終了月へ移す。
- 表示月の候補を上記の範囲に制限する。
- 現在月の判定は利用端末の年月を基準にする。月途中の比較注記は表示しない。月次集計の `updated_at` はこの画面に表示しない。

## 7. 金額とデータの扱い

| 表示項目 | 根拠・規則 |
| --- | --- |
| 計上額 | `total_recorded_amount`。各支出の `recorded_amount` の月合計 |
| カテゴリ別金額 | `category_totals`。確定した明細は `tax_included_amount`、未確定行は印字額 `amount` を使い、数量を再乗算しない |
| 明細合計 | `category_totals` の全カテゴリの合計。計上額と同じ総額として扱わない |
| 明細数 | `detail_count`。商品の数量合計ではない |
| 税込み確定明細数 | `confirmed_detail_count`。未返却の旧集計では0と扱う。`detail_count` との差を未確定件数として明示する |

- レコードのない月は `集計なし` と表示し、0円を補完しない。棒は描かず月の位置とラベルを残す。月別支出へのリンクは残す。
- レコードがあり金額が0なら `0円`。負数なら `-1,000円` のように表示し、グラフは0を基準に下方向（モバイルは左方向）へ伸ばす。すべて0円でも0の基準線を残す。
- グラフは同じ期間内で共通の線形尺度を使い、0を省略しない。負数がある場合は正負双方の目盛りを設ける。
- カテゴリ名は[ユビキタス言語](../../ddd/ubiquitous-language.md#カテゴリ)に合わせる。「分類不能」と「その他」をまとめない。金額降順、同額は定義順にし、0円のカテゴリは省略する。
- カテゴリ内訳は修正後の集計値を表示する。APIにはAI由来・手動編集済みの内訳がないため、月単位の編集バッジや推定比率は作らない。個別の由来は月別支出・支出詳細で確認する。
- 計上額と明細合計の差を「調整額」と断定しない。読取金額と明細合計の不一致もあり得るため、参考欄の説明で意味の違いを示す。
- `confirmed_detail_count < detail_count` の月は、未確定件数と印字額が内訳に混在することを明示する。積み上げ棒は明細の参考内訳として表示し、税込みの構成比とは呼ばない。

## 8. 画面状態

| 状態 | 表示と次の操作 |
| --- | --- |
| 初回取得中 | 共通レイアウトの `Suspense` で「月ごとの支出を読み込み中」。0円や空状態を先に出さない |
| 取得成功 | グラフ・参考内訳を同じレスポンスから表示する |
| 全件空 | 下記の案内と取り込みへのリンクを表示。期間操作・空のグラフは出さない |
| 表示期間だけ空 | 期間操作を残し「この期間の集計はありません」。グラフの月名と「集計なし」のラベルを残す |
| 参考月の集計なし | 「この月の集計はありません」と月別支出へのリンクを表示 |
| 明細0件 | 計上額は通常表示し、参考欄は「この月の明細はありません」 |
| 明細あり・全カテゴリ0円 | 「明細合計 0円」と明細数を表示。集計なしとは区別する |
| 再取得中 | 現在の内容を維持し、ボタンを「再読み込み中…」にする。開始から3秒間は連打を防ぎ、取得完了後のクールタイム中は解析履歴と同じく薄い緑の進行表示と残り秒数をボタン内に示す |
| 初回取得失敗 | 「月ごとの支出を取得できませんでした」と `[ 再試行 ]`。期間や金額を推測して表示しない |
| 再取得失敗 | 内容を残して「更新できませんでした。前回取得した内容を表示しています」と `[ 再試行 ]` |

全件空:

```text
ダッシュボード
────────────────────────────────────
まだ月ごとの集計がありません。
レシートを取り込むと、登録された支出を
月ごとに確認できます。

レシートを取り込む >
取り込み済みの場合は、解析履歴を確認 >
[ 再読み込み ]
```

定期取得はしない。再読み込みは保存済み集計の取得であり、集計再構築ではない。支出編集から戻る際は集計キャッシュを無効化して再取得し、修正前の金額を確定値として残さない。

## 9. 表現・アクセシビリティ

- 色: 背景・文字・補助文字・区切り線は既存トークン。計上額の棒は `--color-text-muted`、カテゴリ別は共通カテゴリ色、主要リンクと現在地は `--color-primary`。装飾用グラデーション・影・画像は不要。
- 文字: 既存の日本語 system font stack、本文 `16px`、補助 `14px` 以上、ページ見出し `24px` を目安にする。操作部品も同じフォントを継承し、金額は tabular numbers。
- 余白: 領域間 `32px`、見出しと内容 `16px`、行内 `8px`、月別行の上下 `16px`。新たな色・余白トークンを増やさない。
- 形: カテゴリ一覧は行区切り、明細合計などのまとまりは枠で囲む。操作部品は既存の角丸と枠線を使う。
- 操作: 遷移はリンク、棒の月選択と再取得はボタン、開始月・終了月はラベル付き選択欄。タップ領域は最低 `44px × 44px`。短い計上額の棒でも月の操作領域は44px以上確保する。
- 読み上げ: 棒のボタンには「2026年9月のカテゴリ別内訳を表示」のような名前を付ける。グラフには見出しと説明を付け、各棒の金額をテキストでも読めるようにする。
- キーボード: 開始月・終了月 → 再読み込み → 各月の棒と月名 → 明細リンクの順に操作できる。フォーカスを明示し、正確な金額は常にテキストで確認できるようにする。
- 動き: focus・選択状態の短い変化に限定し、棒が伸びる演出を入れない。読み込み表示は `prefers-reduced-motion` に従う。

## 10. API設計

### GET /monthly-summaries

各月の `confirmed_detail_count` は税込み明細額が確定した行の件数。既存の月次集計で属性がない場合は0として返す。`category_totals` は確定行の税込み額と未確定行の印字額を合わせた参考内訳である。

月次集計一覧を取得する。`year_month` 降順、外部向けページネーションなしで、表示期間の切り替えは取得した一覧から行う。

以下はレスポンス例。実際のレスポンスは定義済み全カテゴリを `category_totals` に含める。

```json
{
  "monthly_summaries": [
    {
      "year_month": "2026-09",
      "total_recorded_amount": 128500,
      "expense_count": 25,
      "detail_count": 120,
      "category_totals": {
        "food": 86000,
        "daily_goods": 22500,
        "social": 15000,
        "other": 5000,
        "unknown": 12000
      },
      "updated_at": "2026-09-15T12:01:00Z"
    }
  ]
}
```

APIから得られない予算・収入・残高・AI精度・未確認件数は追加しない。`POST /monthly-summaries/{yyyy-MM}/rebuild` はダッシュボードの通常操作に含めない。

### POST /monthly-summaries/{yyyy-MM}/rebuild

保存済みの支出と支出明細から指定月の月次集計を再構築する。支出編集からの反映と集計復旧に利用し、ダッシュボードの通常操作には表示しない。レスポンスは `GET /monthly-summaries` の要素1件と同じ形で、定義済みの全カテゴリを `category_totals` に含める。

```json
{
  "year_month": "2026-09",
  "total_recorded_amount": 128500,
  "expense_count": 25,
  "detail_count": 120,
  "category_totals": {
    "food": 86000,
    "daily_goods": 22500,
    "medical": 0,
    "transport": 0,
    "utilities": 0,
    "entertainment": 0,
    "social": 15000,
    "clothing": 0,
    "education": 0,
    "other": 5000,
    "unknown": 12000
  },
  "updated_at": "2026-09-22T01:00:00Z"
}
```

## 11. 実装の確認項目

HTMLモックでの表示・操作確認とは別に、実際のAPIや画面遷移と接続した状態で検証する。

- 360px / 390px / 768px / 1280px で、ナビ・期間操作・長い金額が切れず、横スクロールしない。
- 月ごとの金額と推移、参考内訳の順に読み取れ、カテゴリ合計を計上額として誤認しない。
- 棒から内訳月を切り替え、月名から月別支出へ遷移し、戻ると表示期間と位置が復元する。
- 年またぎ、前月欠損、月途中、0円、負数、全件空、期間内だけ空の表示を確認する。
- 再取得中・失敗時に既存の金額を維持し、再試行と支出編集後の更新ができる。
- 金額の桁揃え、本文と補助文字のサイズ、コントラスト、余白、focus表示、44pxの操作領域を確認する。
- 棒の形や色を読み取らなくてもテキストの金額を確認でき、すべての主要操作をキーボードで行える。

## 12. 対象外

- 予算管理、前年比、ランキング、分析コメント。まず月ごとの金額と推移に絞る。
- 画像によるデザイン案。既存デザインシステムに沿った画面と CSS によるグラフを成果物とする。
